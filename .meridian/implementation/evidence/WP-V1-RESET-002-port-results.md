## Defects fixed

**Defect 1 — self-referencing declarations.** 44 entries listed their own declaring heading
as a reference. The port removes the declaration site from the reference set.

**Defect 2 — no-argument crash.** Not applicable to the port: the subcommand is dispatched
by the existing argument parser and a missing specoment produces a diagnostic naming the
path, not a panic.

**Defect 3 — 31 identifiers counted but never indexed.** Cause was ordering: `all_ids` was
computed before range-declared identifiers were merged into the owner map. The port merges
weak range declarations into the declared map before emission, so the count and the output
are the same collection by construction rather than by coincidence. Recovered families:
`AI-POLICY-001..008`, `NORM-MIG-001..012`, `CODEHEALTH-001..004`, `OPEN-001..004`,
`FWK-001..003`.

**Defect 4 — letter-suffixed collapse, two shapes.** The reference right boundary
`(?![0-9-])` excluded digits and hyphens but not letters. The port's boundary is a named
predicate with its own tests. All five identifiers now resolve distinctly:
`NETPROJ-006A`, `NETPROJ-006B`, `NETPROJ-006C`, `NETPROJ-006D`, `SCM-010A`, alongside their
stems `NETPROJ-006` and `SCM-010`.

Shape B (`SCM-010A`) is worth separating: because its heading declares both identifiers on
one line, the reference generator's duplicate guard — which compares line numbers — never
fired, so it was overwritten with no signal at all. A test written only against shape A
passes while shape B still loses an identifier.

## Defect 5 — newly found during implementation: SD-006

The reference generator classifies an identifier as retired-v0.5 by bare prefix match, and
its prefix list includes `RG`. `RG-TOR-001` is the **only** `RG-*` identifier in the entire

Because the retired-v0.5 category is exempt from the undeclared count, absorbing a live v1
identifier into it is what made **"0 undeclared" read as true**. The port drops `RG` from
the retired prefix list and `RG-TOR-001` is now reported honestly as undeclared.

contract. Recorded as an owner decision rather than resolved by the agent, because giving

## Test-design defect found and fixed during implementation

The first version of the integration tests read and wrote the real `governance/` files
without synchronisation. Rust runs tests in parallel, so the tampering test raced the
determinism test and both failed for the wrong reason. Serialised behind a mutex. Recorded
because an intermittently-failing test that is "fixed" by rerunning is how a real defect
gets dismissed as flake.

The trigger fired, so the trade was re-examined on `LEGAL-006`'s grounds.

**SHA-256 — decision holds.** The argument was never line count; it was that `sha2` is
absent from the lockfile entirely and pulls roughly five to seven crates into the graph to
hash one file. That cost is unchanged by this module being 152 lines rather than 90. The
code is verified against the NIST vectors, the padding cliff at lengths 55/56/63/64/65, and
a differential property test over random lengths asserting that mutating any single byte
including the last changes the digest.

**Scanner — decision holds, but the margin is narrower than the plan implied.** The argument
was API fit: placement classification (backticked / heading-initial / mid-heading) is not
something a pattern returns, so `regex` would still need the surrounding logic. Realistic
comparison is roughly 90 lines with `regex` against 138 without — a saving of about 50 lines
in exchange for a new direct dependency and a `LEGAL-005` provenance record.

Disclosed rather than buried: **the plan implied a larger advantage than the implementation
supports.** What tips it is corroborating evidence gathered during implementation rather
than argued in advance — the first draft of `match_at` consumed letters and digits together
as one segment, read `SCM-010A` as the four-character segment `010A`, failed the three-digit
test and rejected the identifier outright. That is precisely the class of defect the API-fit
argument predicted, it appeared within minutes of writing the code, and it was caught
immediately by a named test rather than by a lookahead's interaction with a conditional.

**Total production estimate was accurate.** Real production code across all five modules is
829 lines against a ~820 estimate. The `+1316` figure `git diff --numstat` reports for
`src/` includes 300 lines of inline test modules and 176 lines of comments. Only the
infrastructure sub-bound was exceeded, not the package estimate.

## Two defects found after the first commit, by the tests rather than by review

The full `cargo test --workspace` run exited 101. Both failures were real and both were mine.

**Circularity.** The Appendix H.5 stamp recorded repository HEAD as
`generated_at_source_checkpoint`. HEAD moves for reasons unrelated to the specoment —
including the very commit that lands the projections — so every projection was stale the
instant it was committed, `project --check` could never pass, and the determinism test
compared bytes that always differed. A check that can never pass trains people to ignore it,
which is worse than not having one.

Fixed by not stamping a volatile value. Appendix H.5 asks for
`generated_at_source_checkpoint = <revision>`; in a single-root-authority repository the
revision *of the source* is the specoment itself, so the stamp is now
`specoment:<canonical digest>`.

An intermediate fix — excluding the checkpoint line from the comparison — was written and
then discarded. It removed the circularity but left a hole where a hand-edit to the excluded
line would go undetected. Making the output genuinely deterministic is better on every axis:
byte-identical regeneration holds literally, the comparison needs no exceptions, and
staleness detection is exact.

**Fail-open exit code.** `project --check` printed staleness and returned success. CI would
have gone green while the projections misrepresented the authority — precisely the failure
Appendix D requirement 7 exists to prevent. The problems now reach the issue list and the
command exits 1.

Verified end to end: clean tree exits 0; a one-line tamper exits **1** and reports
`stale-projection` naming the file; regeneration is byte-identical across runs.

**Worth recording about the process.** The first commit passed six gates — targeted tests,
fmt, clippy, `spec check`, `project --check`, `git diff --check` — and still carried both
defects. `project --check` passed only because it was run before the commit that
invalidated it, and it could not have failed in any case. The workspace run caught it. This
is the concrete argument for running proportional gates before closure rather than trusting
targeted ones, and for the plan's insistence that a check which cannot fail is not evidence.
